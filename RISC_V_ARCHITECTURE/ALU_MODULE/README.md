# 32-bit RISC-V ALU

## Description

This module implements the 32-bit Arithmetic Logic Unit used in the EX stage of the pipelined RISC-V processor.

The ALU performs arithmetic, logical and comparison operations based on the alu_operation signal generated by the ALU Control Unit.

## Inputs and Outputs

| Signal | Width | Description |
|--------|-------|-------------|
| operand_A | 32-bit | First operand, normally obtained from rs1 |
| operand_B | 32-bit | Second operand selected from rs2 or the immediate value |
| alu_operation | 4-bit | Selects the required ALU operation |
| alu_result | 32-bit | Result of the selected operation |
| zero | 1-bit | Indicates that the ALU result is zero |

The operands can also be replaced by forwarded values when a data dependency is detected in the pipeline.

## Supported Operations

| alu_operation | Operation | Usage |
|---------------|-----------|-------|
| 0000 | ADD | ADD, ADDI, LW and SW |
| 0001 | SUB | SUB and BEQ |
| 0010 | AND | Bitwise AND |
| 0011 | OR | Bitwise OR |
| 0100 | XOR | Bitwise XOR |
| 0101 | SLT | Signed Set-Less-Than |
| Others | Default | Result set to 0 |

For LW and SW, addition is used to calculate the memory address using rs1 and the immediate value.

For BEQ, the two source register values are subtracted. If the result is zero, the operands are equal and the zero signal is asserted.

SLT performs a signed comparison between operand_A and operand_B. The signed representation of the operands is considered so that negative values are compared correctly.

## Design

The ALU is implemented using combinational logic and does not contain clocked storage.

Any change in the operands or alu_operation updates alu_result. The calculated result is captured by the EX/MEM pipeline register at the positive clock edge.

The zero signal is generated from alu_result and is used by the branch logic for BEQ comparison.

## Verification

The module was verified using a Verilog testbench covering:

- ADD and SUB operations
- AND, OR and XOR operations
- SLT for true and false conditions
- Signed SLT using a negative operand
- Subtraction resulting in zero
- Default behavior for an unsupported operation

The zero output was also checked to verify its behavior during branch comparison.
