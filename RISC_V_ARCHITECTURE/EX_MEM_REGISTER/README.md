# EX/MEM Pipeline Register

## Description

The EX_MEM_REGISTER is the pipeline register between the Execute (EX) and Memory Access (MEM) stages.

It stores the data and control signals produced during the EX stage and passes them to the MEM stage in the following clock cycle.

## Inputs and Outputs

| Signal | Width | Description |
|--------|------:|-------------|
| alu_result | 32-bit | Result generated by the ALU |
| store_data | 32-bit | Data to be written for store instructions |
| rd | 5-bit | Destination register address |
| zero | 1-bit | ALU zero flag |
| reg_write | 1-bit | Register write enable |
| mem_read | 1-bit | Data Memory read enable |
| mem_write | 1-bit | Data Memory write enable |
| mem_to_reg | 1-bit | Selects memory or ALU result for write-back |
| branch | 1-bit | Branch control signal |

The corresponding outputs contain the registered versions of these signals for use in the MEM stage.

## Operation

All input values are captured at the positive edge of the clock using non-blocking assignments.

For LW and SW instructions, the ALU result represents the calculated memory address.

For SW, store_data carries the value that will be written into Data Memory. For arithmetic instructions, the ALU result is carried forward toward the write-back stage.

When reset is asserted, the stored data and control signals are cleared to zero.

## Store Data Path

For store instructions, store_data is kept separate from the second ALU operand.

SW uses the immediate value as the second ALU operand for address calculation:

address = rs1 + immediate

However, the actual data written to memory comes from rs2. Therefore, the rs2 value is carried separately through the EX/MEM pipeline register as store_data.

## Verification

The EX/MEM register was verified during the complete pipelined processor simulation.

The simulation was checked to confirm that the ALU result, store data, destination register address and control signals are transferred from the EX stage to the MEM stage at the positive clock edge.

Reset behavior was also checked to confirm that the registered outputs are cleared correctly.
